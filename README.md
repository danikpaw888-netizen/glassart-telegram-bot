## Рабочая схема

В личном чате допущенный отправитель заполняет и отправляет заявку. После отправки бот выдает номер и подтверждение постановки в очередь. Полные карточки, просмотр и кнопки выполнения находятся в одной подключенной группе сотрудников. Частной рассылки карточек сотрудникам и администраторам больше нет. Прежние команды списка, поиска и кнопки старых частных карточек не предоставляют доступ к просмотру или смене статуса.

Если группа еще не подключена, заявка сохраняется и ждет подключения. После привязки в группу поступят все сохраненные заявки, включая ранее созданные.

## Подключение группы

1. Добавьте @GlassArtWork_bot в выбранную группу сотрудников и назначьте его администратором группы.
2. От собственного аккаунта отправьте в этой группе `/bindgroup` (при необходимости `/bindgroup@GlassArtWork_bot`). Ваш аккаунт должен быть действующим администратором бота GlassArt и участником группы Telegram. Права администратора самой группы у отправителя команды не требуются.
3. Бот подтвердит подключение и поставит все сохраненные заявки в очередь публикации.

Группа определяется по месту команды, числовой ID вручную вводить не нужно. Для групп с темами команда в конкретной теме привязывает заявки к этой теме. Повторная привязка к другой группе или теме меняет место будущих публикаций и публикует туда сохраненные заявки. Старые сообщения остаются в истории прежней группы, но их кнопки больше не меняют статусы.

Текущую группу и инструкцию можно увидеть командой `/group` у бота или кнопкой «Группа сотрудников». Бот не выбирает группу из архивов по похожему названию.

## Действия сотрудников в группе

Карточка содержит номер GA-000001, общий статус, автора, клиента, тип пленки, позиции стекол, общую площадь и комментарий. На ней только две кнопки: **✅ Выполнено** и **❌ Не выполнено**.

Кнопки доступны реальным участникам подключенной группы; отдельный допуск `/allow` для отметок в группе не нужен. Перед нажатием сервер проверяет членство через Telegram API. Покинувшие группу, пользователи другой группы и произвольные старые карточки не могут менять заявку. Состояние общее для всей заявки, с отметкой ID сотрудника и времени последнего изменения. Меняется текст той же карточки, новая карточка при каждом нажатии не создается.

Одновременные нажатия проверяются по версии заявки. Повтор того же статуса безопасен. Устаревшее нажатие не перезаписывает более новое действие и обновляет карточку. Если сообщение удалили из Telegram, следующая попытка обновления восстановит карточку. Длинные карточки делятся на несколько сообщений; кнопки находятся на последнем.

## Поля заявки

1. Клиент — имя или название компании.
2. Тип, марка и артикул пленки.
3. До 20 позиций стекол. Для каждой: ширина × высота × количество в мм, обработка «есть / нет», толщина в мм. Например `1200 × 1500 × 2`, обработка есть, толщина `4`.
4. Комментарий либо «Пропустить».
5. Проверка карточки, исправление черновика и кнопка «Отправить заявку».

Клиент, пленка, размеры, обработка и толщина обязательны. У каждой позиции могут быть свои обработка и толщина; в одной заявке один тип пленки. Размеры принимаются с точностью до 0,01 мм, толщина — больше 0 и до 1000 мм. Площадь стекол показывается в м² с округлением до 0,001 м². Раскрой и запас пленки не учитываются. Телефон, объект, срок и фото отсутствуют.

Черновик автоматически сохраняется; до отправки его можно исправить или отменить. После отправки в личном чате нет просмотра и редактирования реестра. Старые заявки и ранее собранные данные не удаляются; недостающие параметры старых стекол показаны как «не указана». Старые черновики на удаленных шагах продолжаются с актуального вопроса. Прежние ссылки на фото сохраняются только в данных, интерфейс их не показывает и не отправляет.

## Команды

| Команда | Действие |
|---|---|
| `/menu`, `/start` | Меню отправки заявок |
| `/new` | Новая заявка |
| `/resume` | Продолжить черновик |
| `/cancel` | Отменить текущий ввод |
| `/id` | Свой Telegram ID |
| `/group` | Подключенная группа и инструкция; администратор |
| `/bindgroup` | Подключить группу, команда в самой группе |
| `/allow ID` | Разрешить отправку заявок; администратор |
| `/revoke ID` | Отозвать частный доступ; администратор |
| `/staff` | Список отправителей и администраторов |
| `/admins` | Список и кнопки управления администраторами |
| `/addadmin ID` | Назначить администратора |
| `/removeadmin ID` | Снять права, сохранив доступ отправителя |

Администраторов может быть несколько. Они управляют отправителями, администраторами и привязкой группы. Права последнего администратора снять нельзя. После снятия прав `/revoke ID` полностью закрывает частный доступ. Членство в группе и права на нажатие кнопок определяются отдельно самой группой Telegram.

## Хранение и доставка

Cloudflare Workers принимает webhook. SQLite-backed Durable Object GlassArtRegister, ключ company:glassart, хранит заявки, роли, черновики, историю, обработанные события, постоянную очередь отправки, задания групповых публикаций и ID сообщений групповых карточек. Существующий namespace и секреты сохраняются при обновлении. Тариф аккаунта не меняется.

Заявка, обработанный update_id и очередь фиксируются транзакционно. Telegram-обновление подтверждается после записи. Повтор обновления не дублирует заявку. Исходящие запросы повторяются при временных сбоях и лимитах Telegram через alarms. Редкая авария после отправки сообщения до записи его ID может создать повторное сообщение. Постоянные ошибки доставки отмечаются; заявки остаются в базе. После восстановления прав бота повторите `/bindgroup` в группе для повторной публикации.

Подтверждение отправителю означает сохранение и постановку в очередь, а не подтвержденное появление сообщения в Telegram. Ранее доставленные частные и групповые сообщения при смене режима не удаляются. Отдельного независимого экспорта базы в этой версии нет; для восстановления используются средства SQLite Durable Objects / Point-in-Time Recovery Cloudflare.

## Новое в 3.1

Карточки оформлены как расчет: толщина стекла, пленка и обработка в шапке; при разных параметрах они указываются для каждой позиции. Каждая позиция содержит размеры, количество и площадь, внизу — итоговое число стекол и площадь. Площади округлены до 4 знаков без лишних нулей.

После явного выбора статуса остается одна кнопка «Заказ выполнен» или «Заказ не выполнен». Нажмите ее для повторного выбора двух вариантов и исправления статуса.

Отчет считает все заявки по дате их отправки, а не дате завершения, по часовому поясу Asia/Oral (Казахстан); отдельно показывает общую площадь, число заявок и стекол, площадь выполненных и невыполненных. Проверяется членство в группе. Старые карточки обновляются автоматически при переходе на эту версию.

## Версия 3.1.1

В строке «Отметил» показывается имя и фамилия пользователя Telegram, при их отсутствии — @username. Числовой ID остается только во внутренней истории. Имена прежних авторов отметок запрашиваются через Telegram getChatMember перед обновлением старых карточек; если имя недоступно, показывается «Сотрудник».

## Версия 3.2

Несколько размеров можно отправить одним сообщением, каждую позицию с новой строки. Принимаются пробелы, x, х и ×. Например:

```text
1200 768 4
12345 567 2
```

Затем бот по очереди запрашивает обработку и толщину каждой позиции. Можно добавлять следующие позиции отдельным сообщением или списком. Общий предел — 20 позиций. Если в списке ошибка, сообщение целиком не добавляется, бот показывает номер строки для исправления. Количество по умолчанию — 1.
